## Stats & Metrics

- [ ] **Filter maintenance ingests from coverage metrics** — `stats` skill counts all 25 ingest events, including ones triggered by verify/lint/maintenance agents. Only ingest events with a real numeric Bugzilla `bug_id` should count toward ingest coverage and false confidence rate.

- [ ] **False confidence rate is blind** — `hypothesis_from_wiki` and `hypothesis_correct` fields are never populated. No real bug investigations have been run through the wiki yet. Stats can report hit rate but cannot measure whether wiki hits actually help. Needs real investigation data before this metric is meaningful. *(Partially mitigated: `pre_lookup`/`wiki_read` events now carry a best-effort `bug_id` from the cwd's worktree branch, and stats has a new `wiki_hit_outcome` metric that joins wiki hits to the triage decisions log without needing an ingest event.)*

- [x] **`hypothesis_from_wiki` auto-detection** — Ingest skill now scans the last 8 hours of `pre_lookup` events for `wiki_hit: true` to set `hypothesis_from_wiki` automatically. No engineer action needed.

- [x] **`hypothesis_correct` auto-backfill** — Verify skill now backfills `hypothesis_correct` in matching ingest events after each verify run: `stale_fixed == 0` → true, `stale_fixed > 0` → false. Data grows naturally without any manual review.

- [ ] **`verify-report.md` appearing in most-consulted pages** — Verify agents read `verify-report.md` during maintenance, polluting the most-consulted list. Filter files outside `$WIKI_PATH` content directories (i.e. exclude `verify-report.md`, `lint-log.json`, `usage-log.jsonl`) from wiki_read consultation counts in stats.

## Tiered Retrieval & Aliases (claude-mem-inspired, v0.9.0)

- [x] **Tiered lookup via derived `index.json`** — `lookup` reads a compact `index.json` (names + summaries + aliases) first instead of the full 33 KB `INDEX.md`, falling back when the cache is missing or its mtime no longer matches `INDEX.md`. Regenerated by `lint --full`; incrementally upserted by `ingest`/`add`.

- [x] **Alias-aware pre-lookup** — the hook now splits `Class::Method` names and expands abbreviations via a derived `aliases.txt` (from `glossary.md`), bounded to 5 candidates / 3 files to stay fast. Also broadened trigger coverage to `--symbol/--calls-from/--calls-to/--field-layout`.

- [ ] **Multi-word aliases not captured** — `aliases.txt` generation keeps only single-identifier expansions (e.g. `MDSM→MediaDecoderStateMachine`), so multi-word glossary entries like `EME→Encrypted Media Extensions` are skipped. Fine for grep-term expansion, but lookup could still benefit from them in the `index.json` summaries.

- [ ] **Reconcile incremental index drift** — `ingest`/`add` upsert `index.json` row-by-row; a hand-edit of `INDEX.md` without a lint leaves the cache stale until the next `lint --full` (the mtime guard makes `lookup` fall back safely in the meantime, so this is correctness-safe, just a performance gap).

- [ ] **`bug_id` depends on worktree naming** — the hooks derive `bug_id` from a `[0-9]{6,}` run in the cwd's git branch. Non-worktree workflows (detached HEAD, non-bug branches) yield `null`; `WIKI_BUG_ID` is the explicit override. Consider also reading the active investigation file.

## Confidence Scoring

- [ ] **Implement confidence scoring system** — See debate in session 2026-04-06. Two jobs: (1) maintenance scheduling — low confidence pages are always due for verify; (2) runtime — lookup skill surfaces confidence level so Claude treats low-confidence facts as leads to verify, not ground truth.

- [ ] **Track verify coverage, not just pass/fail** — "High confidence after verify" is misleading when the verify agent only sampled 12 of 30 facts. Track `facts_checked` / `facts_estimated_total` alongside `verify-last` in lint-log.json. A page with 40% coverage should not be marked the same as one with 100% coverage.

- [ ] **Auto-downgrade confidence on code change** — Pages should not silently stay high-confidence after Firefox has accumulated new commits past the verified rev. Use `lint-source-rev` (already tracked in lint-log.json) to auto-lower confidence when the Firefox tree has moved significantly, without waiting for the full interval.

## Audit fixes (v0.10.0)

- [x] **Hook↔lookup handoff was dead** — the pre-lookup hook printed `[WIKI HIT] …` but `lookup` step 4 matched `Wiki hit for '<term>':`, so the "reuse the hook's file list, skip re-grep" fast-path never fired. Aligned `lookup/SKILL.md` to the real `[WIKI HIT]` + indented `path: snippet` format.
- [x] **Nonexistent command names in nudges** — `ingest`/`add`/`verify` told users to run `/firefox-wiki:wiki-verify` / `wiki-add`; the skills are `verify`/`add`. Fixed.
- [x] **`init` step 5 missing slash** — `${CLAUDE_PLUGIN_ROOT}scripts/...` always reported the hook missing. Fixed to `${CLAUDE_PLUGIN_ROOT}/scripts/...`.
- [x] **`architecture/` never verified** — it was in lint/verify interval tables but absent from `verify` Step 1's scan and the `ingest`/`add` verify-nudge buckets, so architecture pages were never nudged or checked. Added (90d).
- [x] **Defensive shims hardened** — the missing-lib `wiki_under_path` shims in `log-wiki-read.sh`/`wiki-lint-trigger.sh` now do a `$WIKI_PATH` boundary match (were substring `firefox-wiki/`, which ignored a custom path and matched `firefox-wiki-backup/`). The two `_active-skill.sh` fallbacks now resolve an absolute plugin root.
- [x] **Trigger-hook test coverage** — added `tests/test-triggers.sh` (12 cases: log-wiki-read bug_id/gating/rel-path, lint-trigger gating, ingest-trigger pattern + self-exclusion) and `tests/run-all.sh`.

- [ ] **Rename the `TERM` variable in `wiki-pre-lookup.sh`** — the query variable is named `TERM`, which shadows/clobbers the terminal-type env var for child processes (grep/find/git/jq). Non-interactive children make the impact ~nil, but it's a footgun. Rename to `QUERY`/`WIKI_TERM` (mechanical, ~15 sites — do carefully).
- [ ] **BSD `grep -E \b` no-op** — the CamelCase fallback in `wiki-pre-lookup.sh` uses `\b`, which BSD/macOS grep ignores (GNU honors it), so the fallback over-matches on macOS. Best-effort term only; low impact.
- [ ] **`wiki_cfg_list` glob/space fragility** — the unquoted `printf '%s\n' $val` split also globs and splits on spaces; fine for the documented identifier-like values, fragile if a `trigger_paths` token contains `*` or a space.

## Configurability — any wiki, any subsystem (v0.10.0)

- [x] **Honor `$WIKI_PATH` everywhere (Tier 1)** — fixed the hardcoded `firefox-wiki/` literal gates in `log-wiki-read.sh` and `wiki-lint-trigger.sh`, and the substring self-exclusion in `wiki-ingest-trigger.sh` (now compares `git rev-parse --show-toplevel` to `$WIKI_PATH`, canonicalized via `pwd -P` for macOS `/var` symlinks). Shared vs personal wiki = which repo `WIKI_PATH` points at.

- [x] **Configurable trigger surface (Tier 2)** — `search_tool`, `trigger_paths`, `source_repo_pattern` live in `$WIKI_PATH/wiki-config.json` (env overrides: `WIKI_SEARCH_TOOL`/`WIKI_TRIGGER_PATHS`/`WIKI_SOURCE_REPO_PATTERN`). Read via the new sourced `scripts/_wiki-config.sh`. `/firefox-wiki:init` creates the config and offers to persist a non-default `WIKI_PATH` into `~/.claude/settings.json`.

- [ ] **`wiki_under_path` does not canonicalize** — `log-wiki-read.sh`/`wiki-lint-trigger.sh` match the tool's `file_path` against `$WIKI_PATH` by string prefix (matches prior behavior). If a user sets a `WIKI_PATH` containing a symlink and the tool reports the resolved path (or vice versa), the gate could miss. Low priority; canonicalizing on every Read hook costs a `cd`+`pwd -P` per call.

- [ ] **Generalize ingest source extraction (Tier 3, deferred)** — the `ingest`/`verify`/`add` skills still assume Firefox sources (Searchfox URLs, Bugzilla, spec distillation). A truly domain-agnostic wiki would need pluggable source verifiers. Out of scope for now — the accuracy machinery is the differentiator.
